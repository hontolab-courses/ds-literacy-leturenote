# 第4回：データの前処理

## この回で学ぶこと

- 現実のデータには**欠損値・外れ値・表記ゆれ・重複**などの「汚れ」が含まれていることを，具体例を挙げて説明できる．
- 機械（プログラム）がそのまま読み取り処理できる形にデータを整える**マシンリーダブル（機械可読）** の考え方と，表づくりの基本ルールを説明できる．
- **tidy data（整然データ）** の3つの条件を説明でき，「分析しにくい表」との違いを見分けられる．
- 変数の4つの**尺度水準**（名義・順序・間隔・比率）を区別でき，それが統計量やグラフの選択につながることを説明できる．
- 前処理の判断が分析結果を左右すること，恣意的な前処理の危うさを説明できる．

## 導入：集計が合わない新歓アンケート

まずは，みなさんの学生生活で実際に起こりそうな場面から始めましょう．

```{admonition} 事例：新歓アンケートの集計に2時間かかった話
あなたは音楽サークルの新歓担当になりました．新入生歓迎イベントの出欠を，紙のアンケートとLINEのメッセージで集め，Excelの表に手入力していきます．回答は40人分．「学部ごとの参加人数を数えて，部長に報告するだけ．30分もあれば終わるだろう」と思っていました．

ところが，学部別に人数を数えてみると，合計が回答者数と合いません．表をよく見ると，同じ学部のはずなのに「経済学部」「経済」「けいざい」と書き方がバラバラで，別々に数えられています．同じ人の回答が2回入力されている行もあれば，学部欄が空欄のままの行もあります．学年も「1年」「１年（全角）」「一年」が混在しています．結局，表を1行ずつ確認して直す作業に2時間かかり，「数える」作業そのものは最後の5分だけでした．
```

この事例の「表を直す2時間」にあたる作業，つまり，**集めたデータを分析できる状態に整える作業**のことを，データサイエンスでは**前処理**（データの前処理，data preprocessing）と呼びます．

データ分析というと，統計量を計算したり，きれいなグラフを描いたり，AIに予測させたりする華やかな場面を想像するかもしれません．しかし現実には，分析者の時間の多くはこの地味な前処理に費やされます．New York Timesの報道記事 {cite}`lohr2014` は，データサイエンティストが「データの収集と準備という地味な労働（janitor work，掃除人の仕事）」に労働時間の50〜80%を費やしていると伝えました．また，産業界の調査（CrowdFlower社による2016年のData Science Report）でも，データサイエンティストの時間の約60%がデータの整理・清掃に費やされると報告されています．「分析の8割は前処理」という言い回しを聞くことがありますが，これらの出典（報道記事と産業調査であり，厳密な学術的推計ではありません）を踏まえると，**「分析の作業時間のおおむね5〜8割は前処理」** と幅を持たせて理解しておくのが誠実です．いずれにせよ，前処理が分析の成否を握る最重要工程のひとつであること——**前処理の重要性**——は，実務でも研究でも広く共有されている認識です．

この時間配分をイメージとして描いたものが {numref}`fig-ch04-pipeline-time` です．分析の流れ全体の中で，前処理がいかに大きな割合を占めるかを確認してください．

## バッドデータ——現実のデータは汚れている

そのままでは分析に使えない，誤りや不統一を含んだデータのことを，俗に**バッドデータ**（bad data）と呼びます．教科書に載っている練習用データはたいてい最初から整っていますが，現実の世界でみなさんが手にするデータ——アンケートの回答，手入力の名簿，ウェブからダウンロードした表——は，ほぼ例外なくどこかが汚れています．まずは，バッドデータの代表的な4つの型を，先ほどの新歓アンケートを小さくした例で具体的に見ていきましょう．

以下では，表計算ソフトの代わりにPythonのライブラリ**pandas**を使って表を扱います．本科目ではコードを書けるようになる必要はありません．「機械にデータを読ませるとこう見えるのか」を実感するための材料として，コードと実行結果を眺めてください．

```{code-cell} ipython3
:tags: [hide-input]

# 準備：表データを扱うライブラリを読み込む
import pandas as pd
import numpy as np

# 日本語を含む表の列幅を見やすく調整する設定
pd.set_option("display.unicode.east_asian_width", True)
```

```{code-cell} ipython3
df = pd.DataFrame({
```

### 欠損値

**欠損値**（missing value）とは，本来入っているはずの値が入っていない「穴」のことです．アンケートの記入漏れ，センサーの故障，入力忘れなど，欠損が生まれる理由はさまざまです．上の表では，渡辺さんの学部が入力されておらず，`None`（値がない印）になっています．pandasでは，欠損の数を次のように数えられます．

```{code-cell} ipython3
# 列ごとの欠損値の個数を数える
df.isna().sum()
```

学部に1件の欠損があると表示されました．ここで注意してほしいのは，伊藤さんの「参加希望」です．この欄は空文字（`""`，見た目には何も書かれていない状態）ですが，機械はこれを「空文字という値が入っている」と解釈するため，**欠損としては数えられていません**．人間の目には同じ「空欄」でも，機械にとって「値がない（`None`や`NaN`）」と「空文字が入っている」は別物です．こうした「見えない欠損」は集計ミスの定番の原因で，前処理の段階で欠損として明示しておく必要があります．

欠損値への対処には，欠損を含む行を取り除く，平均値などで穴埋めする，欠損のまま扱える方法で分析する，といった選択肢があります．どれを選ぶかで結果が変わりうることは，本章の後半（前処理の恣意性）で改めて取り上げます．

### 外れ値

**外れ値**（outlier）とは，ほかの値から大きくかけ離れた値のことです．入力ミス（172cmを「17.2」と打つ，単位を間違える）で生じることもあれば，本当にそういう値が存在することもあります．外れ値の怖さは，少数でも集計結果を大きく歪めてしまう点にあります．たとえば，新入生5人に「昨日の睡眠時間（時間）」をきいた結果を集計してみます．4人目の「65」は，おそらく「6.5」の小数点の打ち忘れです．

```{code-cell} ipython3
# 新入生5人にきいた「昨日の睡眠時間（時間）」．65はおそらく6.5の入力ミス
sleep = pd.Series([6.5, 7.0, 6.0, 65, 7.5], name="睡眠時間")

print("平均値:", sleep.mean())
print("中央値:", sleep.median())
```

たった1件の外れ値のせいで，平均睡眠時間は18.4時間という非現実的な値になりました（一方，値を小さい順に並べた真ん中の値である中央値は7.0時間で，実態に近い値を保っています）．外れ値を見つける第一歩は，最大値・最小値を確認したり，[第7回「データの可視化」](ch07-data-visualization.md)で学ぶヒストグラムや散布図でデータの分布を眺めたりすることです．

ただし，**外れ値＝誤りとは限らない**点に注意してください．たとえばアルバイト収入の調査で月30万円という回答があったとき，それは入力ミスかもしれませんが，本当にそれだけ働いて稼いでいる学生かもしれません．明らかな入力ミスと確認できれば修正・除外できますが，確認できない外れ値を「邪魔だから」と安易に消すのは，データの改ざんに近づく危険な行為です．

### 表記ゆれ

**表記ゆれ**とは，同じものを指しているのに文字としての書き方が異なることです．「経済学部／経済／けいざい」「1年／１年（全角）／一年」のほか，前後の余分なスペース，大文字と小文字（「NCU」と「ncu」），日付の書き方（「2026-04-06」「4月6日」「04/06/2026」）など，形はさまざまです．人間は文脈からすべて同じ意味だと分かりますが，機械は**文字列が1文字でも違えば別の値**として扱います．先ほどの表で学部ごとの人数を数えてみましょう．

```{code-cell} ipython3
# 学部ごとの回答数を数える（表記ゆれがあるとどうなるか）
df["学部"].value_counts()
```

実際には経済学部の回答者は3人いるのに，「経済学部」「経済」「けいざい」がそれぞれ別の学部として数えられてしまいました．導入の事例で「集計が合わない」原因の正体はこれです．表記ゆれは，複数人で手入力したデータや，自由記述で集めたデータにほぼ必ず発生します．そもそも自由入力ではなく選択式で集める（データが生まれる段階で汚れを防ぐ）ことが最善ですが，すでに汚れてしまったデータは，後述するデータクレンジングで表記を統一する必要があります．

### 重複データ

**重複データ**（duplicated data）とは，同じ対象についての記録が複数回登録されてしまったものです．同じ人がフォームを2回送信した，紙とLINEの両方で回答した人を二重に入力した，複数のファイルを結合したときに同じ行が重なった，などの理由で生じます．重複をそのままにすると，人数が水増しされたり，特定の回答者の意見が二重に反映されたりして，集計が歪みます．pandasでは，まったく同じ内容の行を次のように見つけられます．

```{code-cell} ipython3
# 内容が完全に一致する行（重複の疑いがある行）をすべて表示する
df[df.duplicated(keep=False)]
```

高橋さんの回答が2行あることが分かりました．なお，現実の重複はもっと厄介で，「高橋」と「高橋 」（末尾にスペース）のように表記ゆれを伴う重複は，このような単純な方法では見つけられません．重複の検出が，表記ゆれの統一とセットで行われることが多いのはこのためです．

## データを機械が読める形に整える

バッドデータの正体が見えてきたところで，「では，どういう状態を目指して整えればよいのか」を考えます．キーワードは**マシンリーダブル**です．

### マシンリーダブル（機械可読）とは

**マシンリーダブル（機械可読，machine-readable）** とは，人間が目で読んで解釈しなくても，機械（プログラム）がそのまま読み取って処理できる形式・状態のことです．ポイントは，**人間にとって読みやすい表と，機械にとって読みやすい表は違う**，ということです．

たとえば，レポートや掲示物でよく見かける次のような表を考えてみましょう．Excelでは，同じ学部が続く部分を「セル結合」してひとつにまとめると，人間には見やすくなります．

| 学部 | 学年 | 参加人数 |
|---|---|---|
| 経済学部 | 1年 | 18 |
|  | 2年 | 7 |
| 人文社会学部 | 1年 | 12 |
|  | 2年 | 6 |

しかし，この表をプログラムで読み込むと，セル結合された部分は**先頭の行にしか値が入っておらず，残りは空欄（欠損）** として読み込まれます．機械はこの表を「2行目の学部は不明」と解釈してしまうのです．同じように，表の上に置かれた飾りのタイトル行，「同上」「〃」という書き方，数値のセルに書き込まれた「約」や「（見込み）」という注釈，色分けだけで表現された情報（赤いセル＝欠席，など）は，どれも人間には伝わりますが機械には伝わりません．見た目の美しさのための工夫が，機械可読性を壊してしまうわけです．

このセル結合の表が，人間と機械のそれぞれにどう「見えて」いるのかを対比したものが {numref}`fig-ch04-human-vs-machine` です．人間には見やすかった表が，機械には学部の分からない歯抜けの表として読まれてしまうことが分かります．

```{figure} ../figures/ch04/ch04-human-vs-machine.svg
:name: fig-ch04-human-vs-machine

:width: 100%

同じ表でも「見え方」が違う——セル結合された部分は，機械には欠損（NaN）として読み込まれる
```

### 表づくりの基本ルール

それでは，機械が読める表はどう作ればよいのでしょうか．統計学者のBromanとWooは，スプレッドシート（Excelなど）でデータを整理するときの実務的な推奨事項をまとめています {cite}`broman2018`．本章に関わる要点を，かみ砕いて紹介します．

- **一貫性を保つ**：同じものは常に同じ書き方で記録する．「経済学部」と決めたら全行で「経済学部」と書く．欠損の印も（たとえば「NA」に）統一する．
- **日付はYYYY-MM-DD形式で書く**：「2026-04-06」のような国際規格（ISO 8601）の形式を使う．「4/6」のような書き方は，国や設定によって4月6日とも6月4日とも解釈されるうえ，Excelが日付を勝手に別の形式に変換してしまう事故の原因にもなる．
- **空セルを残さない**：値が「ない」のか「入力し忘れた」のか区別がつかなくなる．欠損なら欠損と分かる印を明示的に入れる．
- **1つのセルには1つの情報だけを入れる**：「172cm」のように数値と単位を混ぜない（数値の172だけを入れ，単位は列名で示す）．「佐藤（会計係）」のように名前と役職を混ぜず，別の列に分ける．
- **セルを結合しない**：前節で見たとおり，機械には空欄として読まれてしまう．
- **生データ（raw data）を保存し，手を加える前の状態を残す**：整形は元ファイルのコピーに対して行い，「何をどう直したか」を後から確認できるようにする．

これらのルールは，特別な専門技術ではなく「書き方の習慣」です．みなさんがこれからレポートやサークル運営でExcelの表を作るとき，このルールを守るだけで，その表は将来の自分や他人が分析に使える「資産」になります．

### データクレンジング

すでに汚れてしまったデータの誤りや不統一を検出し，修正・統一・除去して品質を高める作業を**データクレンジング**（data cleansing，データクリーニングとも呼びます）と呼びます．前処理の中心的な作業です．先ほどの新歓アンケートの表を，実際にクレンジングしてみましょう．ビフォー（`df`）とアフター（`df_clean`）を見比べてください．

```{code-cell} ipython3
# 元データのコピーに対してクレンジングを行う（生データdfはそのまま残す）
df_clean = df.copy()

# (1) 完全に同じ内容の行（重複）を取り除く
df_clean = df_clean.drop_duplicates()

# (2) 学部名の表記ゆれを統一する
df_clean["学部"] = df_clean["学部"].replace(
    {"経済": "経済学部", "けいざい": "経済学部"}
)

# (3) 学年の表記ゆれを統一し，数値にそろえる
df_clean["学年"] = df_clean["学年"].map(
    {"1年": 1, "１年": 1, "一年": 1, "2": 2}
)

# (4) 参加希望の表記ゆれを統一し，空文字は欠損値として明示する
df_clean["参加希望"] = df_clean["参加希望"].replace(
    {"参加します": "参加", "": np.nan}
)

df_clean
```

重複していた高橋さんの行が1行にまとまり，学部・学年・参加希望の表記が統一され，伊藤さんの「見えない欠損」も欠損値（`NaN`）として明示されました．この状態で学部ごとの人数を数え直すと，今度は正しく集計できます．

```{code-cell} ipython3
# クレンジング後にあらためて学部ごとの人数を数える
df_clean["学部"].value_counts()
```

経済学部3人，人文社会学部1人，芸術工学部1人（それに学部不明1人）という，実態どおりの集計になりました．今回は7行の表なので目視でも直せますが，行数が数万・数百万になっても，プログラムによるクレンジングなら同じ手順で処理できます．これが，データをマシンリーダブルに保つことの威力です．

### 前処理は中立な作業ではない——前処理の恣意性

ここまで読むと，前処理は「誰がやっても同じ結果になる機械的な作業」に見えるかもしれません．しかし実際には，前処理には**分析者の判断**が何度も入り込みます．欠損値を含む行を捨てるのか，穴埋めするのか．外れ値を除外するのか，残すのか．「参加します」を「参加」と同じとみなすのか，別の回答として区別するのか．こうした判断のひとつひとつが，最終的な集計値や分析結果を変えうるのです．これを**前処理の恣意性**と呼ぶことにします．

たとえば，先ほどの睡眠時間の例で「65」を除外すれば平均は約6.8時間，除外しなければ18.4時間で，報告される「新入生の平均睡眠時間」はまったく別物になります．また，満足度アンケートで「無回答の人」を単純に除外して平均を出すと，もし不満な人ほど回答してくれない傾向があった場合，平均満足度は実態より高く見積もられます．どちらの例でも，前処理の判断そのものが結果をつくっているのです．

```{warning}
**恣意的な前処理はデータの改ざんと紙一重です**．「都合の悪い外れ値を消したらきれいな結果が出た」「欠損の扱いをいろいろ試して，いちばん見栄えのよい結果を採用した」——こうした処理は，意図的であれば研究不正（改ざん）ですし，無自覚であっても読み手を誤った結論に導きます．前処理で心がけるべきことは次の3点です．(1) 生データを必ず残す．(2) どのような基準で何を修正・除外したかを**記録し，報告に明記する**（「明らかな入力ミス1件を除外した」など）．(3) 判断に迷う処理は，処理の前後で結果がどう変わるかを確認する．前処理は「隠れた分析」であり，透明性が命です．
```

## tidy data（整然データ）——分析しやすい表のかたち

クレンジングでデータの「値」をきれいにしても，表の「構造」が分析に向いていないことがあります．統計学者のHadley Wickhamは，分析しやすい表の標準形として**整然データ**（tidy data）という考え方を提唱しました {cite}`wickham2014`．

### tidy dataの3つの条件

tidy dataとは，次の3つの条件を満たす表のことです {cite}`wickham2014`．

1. **各変数が1つの列をなす**（1列＝1変数）：「学部」「学年」「参加人数」のように，測っている項目ひとつごとに列がひとつ対応する．
2. **各観測が1つの行をなす**（1行＝1観測）：「誰それの回答」「何月の売上」のように，観測ひとつごとに行がひとつ対応する．
3. **各観測単位の類型が1つの表をなす**（1表＝1種類）：「回答者の名簿」と「イベントの一覧」のように種類の違うデータは，1枚の表に無理に詰め込まず，別々の表に分ける．

ここで**変数**（variable）とは，学部・学年・参加人数のように，観測対象ごとに値が変わりうる測定項目のことです．tidy dataの利点は，**どんなデータでも同じ形になっているので，集計・分析・可視化の道具がそのまま使える**ことです．pandasのようなライブラリも，[第5回](ch05-data-analysis.md)・[第6回](ch07-data-visualization.md)で登場する分析・可視化の道具も，基本的にtidy dataを前提に設計されています．

### 「横持ち」の表をtidyに変換する

tidy dataの反対例としてもっともよく出会うのが，いわゆる**横持ち**の表です．たとえば，サークルの各イベントの参加人数を学年別にまとめた次の表を見てください．人間が一覧するには便利な形です．

```{code-cell} ipython3
# 横持ちの表：学年ごとの参加人数が「列」として横に並んでいる
df_wide = pd.DataFrame({
    "イベント名": ["新歓BBQ", "春合宿", "七夕ライブ"],
    "1年生": [18, 10, 12],
    "2年生": [7, 8, 6],
    "3年生": [3, 5, 4],
})
df_wide
```

この表では，「学年」という変数の値（1年生・2年生・3年生）が**列の名前**になってしまっています．「1列＝1変数」の条件に照らすと，本来この表の変数は「イベント名」「学年」「参加人数」の3つのはずです．このような表は，たとえば「学年別の合計参加人数」を計算したいときに扱いにくくなります．そこで，列名に隠れていた「学年」を1つの列として取り出し，縦長のtidyな形（**縦持ち**）に変換します．

```{code-cell} ipython3
# 横持ち → 縦持ち（tidy data）への変換
df_tidy = df_wide.melt(
    id_vars="イベント名",     # そのまま残す列
    var_name="学年",          # 列名だった「1年生」などを値として持つ新しい列
    value_name="参加人数",    # 表の中身の数値を持つ新しい列
)
df_tidy
```

1行が「あるイベントの，ある学年の，参加人数」という1つの観測になり，「イベント名」「学年」「参加人数」がそれぞれ1列になりました．この形にしておけば，学年別の集計も1行のコードで済みます．

tidy dataの3つの条件と，いま行った横持ち→縦持ちの変換をまとめて図解したものが {numref}`fig-ch04-tidy-data` です．列名だった「1年生」「2年生」「3年生」が，「学年」という1つの列の**値**へ移動していることを，色の対応で確認してください．

```{figure} ../figures/ch04/ch04-tidy-data.svg
:name: fig-ch04-tidy-data
:alt: 上段はtidy dataの3つの条件の図解で，小さな表の上に，各変数が1つの列をなすことを縦の色帯，各観測が1つの行をなすことを横の色帯，各観測単位の類型が1つの表をなすことを表全体を囲む枠で示している．下段は横持ちの表df_wideから縦持ちのdf_tidyへの変換図で，列名だった1年生・2年生・3年生が学年という列の値に移動する様子を，学年ごとの色と3本の矢印で示している
:width: 100%

```

```{code-cell} ipython3
# tidyな形なら，学年別の合計参加人数の集計も簡単
df_tidy.groupby("学年")["参加人数"].sum()
```

大事なのは，横持ちの表が「悪い表」だということではない，という点です．横持ちは人間が読むための**見せる表**として優れています．一方，tidy dataは機械が処理するための**分析する表**の標準形です．目的に応じて2つの形を行き来できること，そして分析の前には tidy な形に整えておくこと——これがデータを扱ううえでの基本作法です．

## 変数の型と尺度水準

前処理の仕上げとして，表の各列（変数）が**どんな種類の値なのか**を確認する作業があります．実は，変数の種類によって「やってよい計算」と「意味をなさない計算」が決まっており，これを取り違えると，形式上は計算できても意味のない分析結果が生まれてしまいます．

### 質的変数と量的変数

変数は大きく2つに分けられます．**質的変数**（カテゴリカル変数）は，学部・血液型・参加希望のように，値が「分類」を表すものです．**量的変数**は，参加人数・身長・気温のように，値が「量」を数値で表すものです．学年（1年・2年…）のように数字で書かれていても，足し算やかけ算に意味があるとは限らないため，「数字で書かれているか」ではなく「値が量を表しているか」で見分けるのがコツです．

### 4つの尺度水準

この分類をさらに細かくしたのが**尺度水準**（scales of measurement）です．心理学者のStevensは1946年の論文で，変数の測定水準を次の4つに整理しました {cite}`stevens1946`．

| 尺度水準 | 意味 | 例 | できること |
|---|---|---|---|
| **名義尺度** | 値は分類のラベルにすぎず，順序もない | 学部，血液型，会員番号 | 同じか違うかの区別，度数を数える |
| **順序尺度** | 値に順序はあるが，間隔は等しいとは限らない | 満足度（5段階），成績評価（S/A/B/C），服のサイズ（S/M/L） | 上と同じ＋大小の比較，並べ替え |
| **間隔尺度** | 値の間隔（差）に意味があるが，ゼロは便宜的な位置にすぎない | 摂氏の気温，西暦年 | 上と同じ＋差の計算（平均など） |
| **比率尺度** | 間隔に加え，ゼロが「何もない」ことを表す | 身長，金額，参加人数，時間 | 上と同じ＋比の計算（「2倍」が言える） |

名義尺度と順序尺度が質的変数に，間隔尺度と比率尺度が量的変数に対応します．いくつか補足しましょう．

- **会員番号や学籍番号は名義尺度**です．数字で書かれていますが，番号の平均を計算しても何の意味もありません．数字＝量的変数ではない，という典型例です．
- **順序尺度は「間隔」を保証しません**．満足度の「5と4の差」と「2と1の差」が同じ大きさだという保証はないため，満足度の平均値は本来は慎重に扱うべき値です（実務では慣習的に平均が使われますが，その暗黙の仮定は意識しておきましょう）．
- **間隔尺度と比率尺度の違いはゼロの意味**です．摂氏0度は「温度がない」ことを意味しない便宜的な基準点なので，「20度は10度の2倍暑い」とは言えません（間隔尺度）．一方，金額0円は「お金がない」ことを表すので，「2000円は1000円の2倍」と言えます（比率尺度）．

4つの尺度水準の関係を階段にたとえて整理したものが {numref}`fig-ch04-scale-levels` です．上の段は下の段の性質をすべて受け継いでおり，段を上るほどできる計算が増えていきます．

```{figure} ../figures/ch04/ch04-scale-levels.svg
:name: fig-ch04-scale-levels
:alt: 名義尺度，順序尺度，間隔尺度，比率尺度の4段を上り階段として描いた図．名義尺度は同じか違うかを区別できる（例は学部・血液型），順序尺度は大小の比較・並べ替えが加わる（例は満足度），間隔尺度は差の計算が加わる（例は摂氏の気温），比率尺度は比の計算が加わりゼロが何もないことを表す（例は金額・身長）．上の段ほどできる計算が増えるという矢印と，名義・順序が質的変数，間隔・比率が量的変数にあたるという括りが付いている
:width: 100%

4つの尺度水準の階段——上の段ほどできる計算が増える．名義・順序尺度が質的変数に，間隔・比率尺度が量的変数に対応する
```

### 尺度水準が分析と可視化を決める

尺度水準をわざわざ学ぶのは，用語を暗記するためではありません．**尺度水準が，その後の分析と可視化における道具選びの基準になる**からです．

- [第5回「データの分析」](ch05-data-analysis.md)では，データを要約する統計量（平均値・中央値・最頻値など）を学びます．どの統計量が使えるかは尺度水準で決まります．たとえば名義尺度に使えるのは最頻値だけで，平均値が意味を持つのは間隔尺度以上です．
- [第7回「データの可視化」](ch07-data-visualization.md)では，データの型に応じたグラフの使い分けを学びます．質的変数の分布は棒グラフ，量的変数の分布はヒストグラム，量的変数同士の関係は散布図——というように，グラフ選びの出発点も変数の型です．

前処理の段階で「この列は何尺度か」を一度確認しておくことは，次回以降のすべての作業の土台になります．変数の型の確認までを含めて前処理，と覚えておいてください．

## 活用事例：政府統計の「機械判読可能なデータ」ルール

マシンリーダブルの考え方は，個人の作業のコツにとどまらず，国のデータ整備の方針にもなっています．

日本の政府統計は，政府統計の総合窓口「e-Stat」などを通じて，誰でも無料でダウンロードできるオープンデータとして公開されています．ところが従来，公開されるExcelファイルの多くは，セルの結合，1つのセルに詰め込まれた注釈，飾りのための空行・空列など，「人間が印刷して読む」ことを前提とした見た目重視の表になっており，プログラムで読み込んで分析しようとすると大量の前処理が必要になることが，データ利用者から長く指摘されてきました．本章で学んだ「人間に読みやすい表と機械が読める表は違う」という問題が，国の統計というスケールで起きていたわけです．

これを受けて総務省は2020年12月，統計表をmachine-readableにするための表記方法のルール（「統計表における機械判読可能なデータ作成に関する表記方法」）を取りまとめました．その内容は，1つのセルには1つのデータのみを入れる，セルを結合しない，数値のセルに単位や注釈の文字を混ぜない，など，本章で紹介したBromanとWooの推奨 {cite}`broman2018` と驚くほど重なっています．つまり，みなさんが本章で学んだ表づくりのルールは，一人ひとりのExcel作業から国のオープンデータ政策まで共通する，データ社会の基本的な約束事なのです．データを「作って公開する側」がマシンリーダブルを心がければ，社会全体で費やされる前処理の時間が減り，データの価値はそれだけ大きくなります．

## まとめ

本章では，データ分析の土台となる前処理について学びました．要点を振り返ります．

- 現実のデータはほぼ例外なく汚れており，分析の作業時間のおおむね5〜8割は前処理に費やされると言われます（New York Timesの報道 {cite}`lohr2014` や産業調査に基づく経験則です）．
- バッドデータの代表的な型は**欠損値・外れ値・表記ゆれ・重複データ**の4つです．機械は人間と違い，文脈を読んでくれません．
- 目指すべき状態は**マシンリーダブル（機械可読）** なデータです．一貫性・YYYY-MM-DD形式・1セル1項目・セル結合の回避といった表づくりのルール {cite}`broman2018` を守り，**データクレンジング**で値を整え，**tidy data**（1列＝1変数，1行＝1観測，1表＝1観測単位）{cite}`wickham2014` の形に構造を整えます．
- 変数には**尺度水準**（名義・順序・間隔・比率）{cite}`stevens1946` があり，使える統計量やグラフを決めます．これは[第5回](ch05-data-analysis.md)・[第6回](ch07-data-visualization.md)への橋渡しとなる重要な視点です．
- 前処理には分析者の判断（**恣意性**）が入り込みます．生データを残し，処理の内容を記録・明記する透明性が不可欠です．

次回の[第5回「データの分析」](ch05-data-analysis.md)では，きれいに整えたデータから意味を読み取る方法——統計量による要約と，相関と因果の区別——を学びます．

## 確認問題

```{admonition} 問1（事例判断）
あるサークルの会計係が作った会計簿の表です．この表を後輩がプログラムで集計しようとしたところ，うまくいきませんでした．**マシンリーダブルの観点から，この表の問題点をできるだけ多く指摘してください．**

| 日付 | 項目 | 金額 | 備考 |
|---|---|---|---|
| 4/6 | 新歓BBQ食材 | 8,500円 | 佐藤が立て替え |
| 4月13日 | 会場費 | 3000 |  |
| 同上 | ジュース代 | 1,200円（うち200円は私費） | |
| 2026-04-20 | コピー代 | ¥400 | |
| 4/27 | 打ち上げ | 未定 | 5月に精算予定 |
```

```{admonition} 解答と解説
:class: dropdown
主な問題点は次のとおりです．

1. **日付の表記ゆれ**：「4/6」「4月13日」「2026-04-20」と形式がバラバラです．年の情報が欠けている行もあります．すべて「2026-04-06」のようなYYYY-MM-DD形式に統一すべきです．
2. **「同上」**：人間には「4月13日」の意味だと分かりますが，機械には「同上」という文字列としか読めません．各行に値そのものを書くべきです．
3. **金額の表記ゆれと単位の混在**：「8,500円」「3000」「¥400」と形式が不統一なうえ，「円」「¥」「,（桁区切り）」が混ざったセルは数値として計算できません．数値（8500，3000，400）だけを入れ，単位は列名（例：金額（円））で示します．
4. **1セルに複数の情報**：「1,200円（うち200円は私費）」は，金額と注記という2つの情報が1セルに入っています．私費の情報は別の列に分けるべきです．
5. **数値の列への文字の混入**：「未定」という文字列が金額の列に入っているため，この列全体が数値として扱えなくなります．未確定なら欠損の印（NAなど）を入れ，事情は備考に書きます．
6. **空セル**：備考の空欄は「特記事項なし」なのか「書き忘れ」なのか区別がつきません（備考のような自由記述欄では許容されることもありますが，データとして使う列では欠損の印を明示すべきです）．
```

```{admonition} 問2（尺度水準の判定）
次の(a)〜(e)の変数は，名義尺度・順序尺度・間隔尺度・比率尺度のどれにあたるか答えてください．

(a) 学籍番号　(b) アンケートの満足度（1〜5の5段階）　(c) 摂氏で測った気温　(d) アルバイトの時給　(e) Tシャツのサイズ（S・M・L）
```

```{admonition} 解答と解説
:class: dropdown
(a) **名義尺度**．数字で書かれていますが，番号は個人を区別するラベルにすぎず，大小や平均に意味はありません．
(b) **順序尺度**．5が4より高い満足を表す順序はありますが，「5と4の差」と「2と1の差」が等しい保証はありません．
(c) **間隔尺度**．差（今日は昨日より3度高い）には意味がありますが，0度は便宜的な基準点であり，「20度は10度の2倍暑い」とは言えません．
(d) **比率尺度**．0円が「対価なし」を意味する絶対的なゼロを持ち，「時給1200円は600円の2倍」という比が意味を持ちます．
(e) **順序尺度**．S＜M＜Lという順序はありますが，サイズ間の間隔が等しいとは言えません．
```

```{admonition} 問3（事例判断：前処理の恣意性）
ある学生団体が，イベント参加者100人に満足度アンケート（1〜5の5段階）を配り，60人から回答を得ました．担当者は無回答の40人を除外して「平均満足度4.2！大好評でした」と報告しようとしています．この報告のどこに注意が必要か，前処理の観点から説明してください．
```

```{admonition} 解答と解説
:class: dropdown
注意すべき点は主に2つあります．

第一に，**欠損（無回答）の扱い**です．無回答の40人は「たまたま出し忘れた」のではなく，「不満だったので回答する気になれなかった」人たちかもしれません．もしそうなら，回答者だけで計算した平均4.2は実際の満足度より高く偏った値になります．無回答を除外するという前処理の判断が，結果を（意図せず）押し上げている可能性があるのです．

第二に，**処理の透明性**です．少なくとも「100人中60人の回答に基づく平均であること（回答率60%）」を報告に明記すべきです．そのうえで，無回答者に偏りがないか（たとえば途中退場した人が多くないか）を検討し，可能なら理由を添えるのが誠実な報告です．なお，このような「回答してくれる人の偏り」は，[第2回「データの収集」](ch02-data-collection.md)で学んだ選択バイアスの問題ともつながっています．
```
