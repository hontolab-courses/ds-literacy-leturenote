第8回：機械学習と予測——AIはどう学ぶのか#

この回で学ぶこと#

  • 「ルールを人が書くプログラム」と「データからパターンを学ぶ機械学習」の違いを説明できるようになる

  • 機械学習の基本形である教師あり学習（例と正解のペアから学ぶ）の考え方と，分類と回帰という2種類のタスクの区別を理解する

  • 学習データとテストデータを分ける理由を，過学習（「暗記」と「理解」の違い）と汎化の観点から説明できるようになる

  • 正解率だけでAIの良し悪しを判断してはいけないこと（精度評価の落とし穴）を，具体例で見抜けるようになる

  • 第1回で紹介した活用事例（画像診断支援・需要予測・推薦システム）の仕組みを識別・予測系AIとして整理し，機械学習の限界（相関に基づく予測・データの偏りの学習）まで含めた全体像をつかむ

前回（第7回）までで，データのライフサイクル——収集→保存・検索→前処理→分析→可視化——の旅はひとまず完結しました．今回からの第8〜10回は，そのライフサイクルの上に立つ発展・横断ブロックです．第2〜7回で学んだ「データを集め，整え，分析する」という営みを，コンピュータが自動で・大規模に行うとどうなるか——それが今回のテーマ，機械学習です．

この章にも，Pythonのコードとその実行結果が登場します．本科目ではコードを書けるようになる必要はありません．コードは「読んで，動かして，実感するための材料」です．出力の数値やグラフを眺めるだけでも，この回の学習目標は達成できます．

導入：迷惑メールフィルタ——毎日働いているのに意識しないAI#

事例：迷惑メールはなぜ自動で振り分けられるのか

みなさんのメールアプリには，「迷惑メール」フォルダがあるはずです．「無料で当選！」「今すぐクリック」といった怪しいメールは，みなさんが何もしなくても自動でそこに振り分けられ，受信トレイにはほとんど届きません．あまりに自然に働いているので意識することすらありませんが，これは立派なAIです．世界中で毎日送られる膨大な迷惑メールを，人間が1通ずつ確認して振り分けることは不可能です．この振り分けを自動で行う「迷惑メールフィルタ」は，AIが社会を支えている最も身近な例の1つと言えます．

では，ここで質問です．あなたは，迷惑メールの見分け方のルールを，自分で全部書き出せますか？

やってみると，これが意外に難しいのです．「『無料』という言葉が入っていたら迷惑メール」——では，大学からの「教科書無料配布のお知らせ」はどうなるでしょう．「知らない差出人からのメールは迷惑メール」——初めて連絡をくれるサークルの先輩やアルバイト先はどうでしょう．ルールを足せば足すほど例外が見つかり，例外に対応するルールを足すと別の例外が生まれます．しかも迷惑メールの送り手は，フィルタをすり抜けようと手口を変え続けます．「無料」を「無｜料」と書く，画像にする——人が書いたルールは，すぐに時代遅れになるのです．

この「ルールを人が全部書き出すことの限界」こそが，今回の出発点です．実際の迷惑メールフィルタは，人が書いた見分け方のルール集ではなく，大量のメールの実例から「迷惑メールらしさ」のパターンを自動的に学び取る仕組み——機械学習——で動いています．この章では，機械学習が「学ぶ」とはどういうことなのかを，小さなコードで作って確かめながら理解していきます．そのうえで，「学んだAIの良し悪しをどう測るか」という評価の問題と，そこに潜む落とし穴，さらに機械学習の原理的な限界までを見ていきます．

機械学習とは——ルールを書くか，データから学ぶか#

2つのプログラムの作り方#

コンピュータに仕事をさせる方法は，大きく2つあります．

1つめは，ルールを人が書くプログラムです．「消費税は価格の10%」「60点以上なら合格」のように，人間が判断のルールを完全に言葉（プログラム）で書き下せる仕事なら，この方法で確実に動きます．電卓も履修登録システムも，基本的にはこの方式です．

2つめが，今回の主役である機械学習（machine learning）です．機械学習とは，人間がルールを1つ1つ書き込む代わりに，大量のデータからコンピュータ自身にパターン（規則性）を見つけさせ，それを予測や判別に使う技術の総称です．機械学習は「経験（データ）から性能を改善していく仕組み」の研究分野として発展してきました [Jordan and Mitchell, 2015]．迷惑メールの見分け方のように，(a) 人間はなんとなくできるのにルールとしては書き出せない仕事や，(b) 状況が変わり続けるためルールを保守しきれない仕事で，機械学習は威力を発揮します．この2つの作り方の違いを 図 37 に並べて示します．

ここで大事なのは，機械学習が魔法ではないことです．コンピュータが見つけているのは，突き詰めれば第5回で学んだ「変数と変数の関係のパターン（相関）」です．つまり機械学習とは，第2〜7回で学んできたデータ分析の営みを，コンピュータが自動で・大規模に行っているものだと考えることができます．だからこそ，データの集め方の偏り（第2回）や前処理の質（第4回）が，そのままAIの振る舞いに影響します．この点は章の後半でじっくり扱います．

教師あり学習——例と正解のペアから学ぶ#

機械学習にはいくつかの学び方がありますが，中心となるのは教師あり学習（supervised learning）です．教師あり学習とは，「入力の例」と「その正解」のペアを大量に与えて，入力から正解を当てるパターンを学ばせる方法です．

  • 迷惑メールフィルタなら，「メールの本文や件名」（入力）と「これは迷惑メール／これは通常メール」（正解ラベル）のペアを大量に与えます

  • 画像診断支援なら，「医用画像」（入力）と「病変あり／なし」（医師がつけた正解）のペアを与えます

「教師あり」という名前は，正解を教えてくれる先生役（正解ラベルつきのデータ）がいる，という意味です．ドリルの問題と解答のセットで勉強するイメージだと思ってください．教師あり学習の全体の流れを 図 38 に示します．例と正解のペアからパターンを学ぶ「学習段階」と，できあがったモデルで新しい入力を判定する「予測段階」の2段構成になっていることを押さえてください．

一方，正解ラベルなしのデータから学ぶ方法もあり，教師なし学習（unsupervised learning）と呼ばれます．教師なし学習の代表的な仕事は，正解を与えられないまま，データの中から「似たものどうしのグループ」を見つけることです．たとえばECサイトが顧客の購買履歴から「まとめ買い派」「新商品好き」といった顧客のグループを自動的に見つけ出す，といった使われ方をします．本章では，これ以降は教師あり学習を中心に話を進めます．

分類と回帰——カテゴリを当てるか，数値を当てるか#

教師あり学習の予測タスクは，当てたい正解の種類によって2つに分けられます．

  • 分類（classification）：正解が**カテゴリ（種類）**であるタスクです．「迷惑メールか，通常メールか」「この顔画像は本人か，別人か」「この画像に病変はあるか，ないか」のように，選択肢の中からどれかを当てます．

  • 回帰（regression）：正解が数値であるタスクです．「明日のこの店の来店客数は何人か」「この時間帯のバスの所要時間は何分か」のように，量を当てます．

迷惑メール判定は分類，来店客数の予測は回帰——この区別は，AIのニュースを理解するときの基本の語彙になるので，覚えておいてください．どちらも「例と正解のペアから学ぶ」という原理は同じで，正解がカテゴリなら分類，数値なら回帰と呼び分けているだけです．2つのタスクの関係を 図 39 に整理します．

次が「学習」にあたる部分です．やることは，それぞれの単語が「迷惑メールの件名」と「通常メールの件名」に何回ずつ現れたかを数え上げる——それだけです．さらに，「迷惑メールでの回数 − 通常メールでの回数」を，その単語の「迷惑メールらしさ」のスコアとして計算しておきます．

# 「学習」＝ラベルごとに単語の出現回数を数え上げる
counts = (
    mails.assign(単語=mails["件名"].str.split())
         .explode("単語")                       # 件名を1単語1行にばらす

# 単語ごとの「迷惑メールらしさ」スコア＝迷惑での回数 − 通常での回数
counts["スコア"] = counts["迷惑"] - counts["通常"]

数え上げの結果を見てみましょう．「無料」「今すぐ」「限定」は迷惑メールに4回ずつ現れる一方，通常メールには一度も現れないので，スコアは+4です．逆に「お知らせ」「日程」は通常メールの側によく現れるのでスコアはマイナスになります．「確認」のように両方に2回ずつ現れる単語は，スコア0——つまりどちらの証拠にもならない中立の単語です．

あとは，新しいメールが来たら，件名に含まれる単語のスコアを合計し，プラスなら迷惑メール，そうでなければ通常メールと判定するだけです．

# 「予測」＝新しい件名に含まれる単語のスコアを合計して判定する
def spam_score(subject):
    words = subject.split()
    return sum(counts.loc[w, "スコア"] for w in words if w in counts.index)

new_mails = [
    "無料 プレゼント 限定 当選",   # いかにも怪しいメール

    "無料 公務員 講座 案内",       # 大学キャリアセンターからの正規の案内
]
for subject in new_mails:
    score = spam_score(subject)
    result = "迷惑メール" if score > 0 else "通常メール"
    print(f"スコア {score:+d} → {result}と判定：「{subject}」")

一方で，3通目を見てください．大学キャリアセンターからの正規の案内「無料 公務員 講座 案内」が，迷惑メールと誤判定されてしまいました．学習データの中で「無料」が迷惑メールの強い証拠（スコア+4）になっていたためです．この分類器は単語の出現回数しか見ておらず，文脈も意味も理解していません．機械学習が学ぶのは，与えられたデータの中のパターンがすべてであり，データにない状況ではあっさり間違える——この性質は，この後の「過学習」や「限界」の話につながる重要な伏線です．

過学習と汎化——「暗記」と「理解」の違い#

本番は「見たことのないデータ」#

ミニ分類器の例で大事なことに気づいたでしょうか．機械学習の目的は，学習に使ったデータを正しく当てることではありません．学習データ24通の判定なら，正解ラベルを丸ごと記憶すれば100%正解できます．しかしそれには何の価値もありません．フィルタの本番の仕事は，明日届く，まだ見たことのないメールを正しく振り分けることだからです．

このように，学習に使わなかった新しいデータに対しても正しく予測できる能力を汎化（generalization：汎用的に通用すること）と呼びます．機械学習の真の目標は，学習データへの正解ではなく汎化です．

ところが，ここに機械学習の最大級の落とし穴があります．データのパターンを一生懸命学ばせるほど，モデルは学習データに含まれる偶然のゆらぎ（ノイズ）まで忠実に学び込んでしまい，かえって新しいデータで外すようになることがあるのです．この現象を過学習（overfitting）と呼びます．機械学習の定番解説でも，過学習は実務家が最も警戒すべき問題として筆頭級に挙げられています [Domingos, 2012]．

過学習は，試験勉強にたとえるとよく分かります．過去問の「答え」を丸暗記した学生は，過去問とまったく同じ問題なら満点を取れますが，数字を少し変えた問題が出るとまるで歯が立ちません．一方，解き方を理解した学生は，過去問での得点は暗記型に及ばなくても，初めて見る問題に対応できます．過学習とは「暗記」であり，汎化とは「理解」である——このイメージを持ってください．

では，AIが「暗記」に陥っていないかは，どうすれば確かめられるでしょうか．答えは試験と同じです．勉強に使っていない問題でテストするのです．機械学習では，手元のデータをあらかじめ2つに分けておきます．

  • 学習データ（訓練データ）：パターンを学ばせるために使うデータ

  • テストデータ：学習には一切使わず，できあがったモデルの実力を測るためだけに取っておくデータ

学習データでの成績がいくら良くても，テストデータでの成績が悪ければ，そのモデルは「暗記」しているだけです．この「データを分けて実力を測る」という手続きは，機械学習の実務における基本中の基本です．

多項式のあてはめで過学習を見る#

過学習が起こる様子を，実際にコードで再現してみましょう．あるカフェが，一日の「時間帯」と「1時間あたりの来店客数」の関係をデータからつかんで，来店客数の予測（回帰のタスクです）に使おうとしている，という設定で考えます．時間帯は，開店直後を0，閉店間際を1とする数値で表します．

まず，架空の観測データを作ります．真の関係は「昼前にかけて増え，午後は落ち着き，閉店前にまた持ち直す」というなめらかな曲線とし，そこに日々の偶然のゆらぎ（ノイズ）を加えます．そして大事な点として，データを学習データ20点とテストデータ15点に分けて用意します．

# 過学習の実演：カフェの「時間帯」と「1時間あたりの来店客数」
np.random.seed(1)  # 乱数の種を固定して再現可能にする

def true_pattern(x):
    # 真の関係：昼前に増え，午後は落ち着き，閉店前に持ち直すなめらかな曲線
    return 70 + 30 * np.sin(2 * np.pi * x)

# 学習データ：等間隔の20の時間帯での観測（真の関係＋偶然のゆらぎ）
x_train = np.linspace(0, 1, 20)
y_train = true_pattern(x_train) + np.random.normal(0, 8, 20)

# テストデータ：別の日に観測した15点（学習には一切使わない）
x_test = np.sort(np.random.uniform(0, 1, 15))
y_test = true_pattern(x_test) + np.random.normal(0, 8, 15)

このデータに，複雑さの異なる3種類の曲線をあてはめてみます．使うのは多項式による曲線あてはめです．多項式の「次数」は曲線の複雑さを決めるツマミで，次数1はただの直線，次数3はゆるやかな曲線，次数15は非常にくねくね曲がれる複雑な曲線です．それぞれをデータに最もよく合うように調整（これが「学習」です）し，学習データとテストデータのそれぞれで，予測が実際の客数から平均して何人ずれたか（平均誤差）を計算します．

# 次数1・3・15の多項式をあてはめ，学習データとテストデータでの誤差を比べる
degrees = [1, 3, 15]
rows = []
fits = {}
for d in degrees:
    coef = np.polyfit(x_train, y_train, d)     # 学習：多項式をデータにあてはめる
    fits[d] = coef
    err_train = np.abs(np.polyval(coef, x_train) - y_train).mean()
    err_test = np.abs(np.polyval(coef, x_test) - y_test).mean()
    rows.append({"次数": d,
                 "学習データでの平均誤差（人）": round(err_train, 1),
                 "テストデータでの平均誤差（人）": round(err_test, 1)})

グラフと誤差の表を照らし合わせると，次のことが分かります．

  • 次数1（単純すぎる）：直線では山と谷のあるパターンを表現できず，学習データに対してもテストデータに対しても誤差が大きいままです．そもそも学べていない状態です．

  • 次数3（ちょうどよい）：真のパターンをうまくとらえ，学習データでもテストデータでも誤差が小さくなっています．これが「理解」した状態，つまり汎化できている状態です．

  • 次数15（複雑すぎる）：曲線が個々の点を律儀に通ろうとして激しくうねっています．その結果，学習データでの誤差は3つの中で最小なのに，テストデータでの誤差は最大になっています．学習データへの当てはまりの良さは，偶然のゆらぎまで「暗記」した結果にすぎず，新しいデータではかえって大きく外すのです．これが過学習です．

この実験から，2つの教訓を持ち帰ってください．第一に，モデルは複雑にすればよいというものではないこと．第二に，「学習データでの成績」でモデルを評価してはいけないこと．次数15のモデルは，学習データでの成績だけを見れば「最優秀」に見えてしまいます．学習に使っていないテストデータで測って初めて，暗記と理解を見分けられるのです．

警告

過学習の危険は，モデルが複雑で，データが少ないほど高まります．「AIの精度99%を達成」という宣伝を見たら，「その精度は，学習に使っていない新しいデータで測ったものか？」と問う習慣をつけてください．学習データで測った精度は，実力の証明にはなりません．

精度評価の落とし穴——正解率99%のワナ#

テストデータで測れば安心か，というと，実はもう1つ大きな落とし穴があります．今度は測り方，すなわち精度評価の落とし穴の話です．

迷惑メールフィルタの話に戻りましょう．いま，手元に1,000通のメールがあり，そのうち迷惑メールは1%——つまり10通しかないとします（残り990通は通常メール）．このデータで，次の「自称AI」の成績を測ってみます．このAIの中身は，何が来ても「通常メール」と答えるだけの，学習も判断も何もしていないインチキです．

# 1,000通のうち迷惑メールは1%（10通）しかないとする
n_all = 1000
n_spam = 10
n_normal = n_all - n_spam

# 「全部通常メール」と答えるだけのインチキAIの成績
correct = n_normal  # 通常メール990通はすべて正解，迷惑メール10通はすべて不正解
print(f"正解率：{correct / n_all:.1%}")
print(f"見逃した迷惑メール：{n_spam}通中 {n_spam}通（すべて見逃し）")

正解率：99.0%
見逃した迷惑メール：10通中 10通（すべて見逃し）

正解率は99.0%．数字だけ見れば超高性能です．しかしこのAIは，肝心の迷惑メールを1通も見つけていません．迷惑メールフィルタとしての仕事を何ひとつしていないのに，正解率が99%になってしまう——種明かしは単純で，そもそもデータの99%が通常メールだからです．このように，当てたい対象（迷惑メール）がデータのごく一部しかない状況を不均衡なデータと呼び，不均衡なデータでは正解率という物差しがほとんど意味をなさなくなります．

比較のために，まじめに学習したAIの成績も見てみましょう．このAIは，迷惑メール10通のうち9通を正しく見つけますが，その代わり通常メール990通のうち20通を誤って迷惑メール扱いしてしまうとします．

# まじめなAI：迷惑メール10通中9通を発見，ただし通常メール20通を誤って迷惑扱い
correct_b = (n_normal - 20) + 9
print(f"正解率：{correct_b / n_all:.1%}")
print("見逃した迷惑メール：10通中 1通")

正解率：97.9%
見逃した迷惑メール：10通中 1通

まじめなAIの正解率は97.9%．なんと，役に立つAIの方が，何もしないインチキAIより正解率が低いという逆転が起きました．正解率だけを物差しにすると，「迷惑メールを9割捕まえる有能なフィルタ」を捨てて「何もしないフィルタ」を選ぶ，という誤った判断をしてしまうのです．

この落とし穴は，笑い話ではなく実害に直結します．たとえば1,000人に1人しかかからない病気を見つける検査AIを考えてください．「全員陰性」と答えるだけで正解率は99.9%になりますが，患者を1人も見つけられない検査に意味はありません．不正送金の検知，設備の故障予知，災害の予兆検知——「めったに起きないが，見逃すと重大なこと」を当てる仕事ほど，正解率という物差しは当てにならないのです．

では，どうすればよいのでしょうか．この科目では詳細には立ち入りませんが，考え方だけ押さえておきましょう．大切なのは，正解率という1つの数字に頼らず，間違いの中身を分けて数えることです．

  • 当てたいもの（迷惑メール・病気など）のうち，どれだけ見逃したか

  • 「当てた」と判定したもののうち，どれだけ濡れ衣（誤検知）だったか

先ほどの例なら，インチキAIは「見逃し10通中10通（全滅）」，まじめなAIは「見逃し10通中1通」で，優劣は一目瞭然です．さらに言えば，見逃しと誤検知のどちらが深刻かは用途によって異なります．迷惑メールなら，多少すり抜けても（見逃し），大事なメールが迷惑フォルダに消える（誤検知）方が困る，という人が多いでしょう．逆に病気の検査なら，見逃しの方がはるかに深刻です．AIの「精度」は，用途に照らして，間違いの中身まで見て初めて評価できる——これが，事例判断で最も役立つ教訓です．

警告

「AIの精度◯◯%」というニュースや宣伝を見たら，次の3つを確認する習慣をつけましょう．

  1. その数字は学習に使っていないデータで測ったものか（過学習していないか）

  2. 当てたい対象はデータの中にどれくらいの割合で存在するか（不均衡なら正解率は当てにならない）

  3. 見逃しと誤検知のそれぞれがどれくらいで，その用途ではどちらが深刻か

機械学習の限界——何を学び，何を学んでいないのか#

ここまでで，機械学習の仕組みと評価を学びました．最後に，機械学習という技術の原理的な限界を2つ押さえます．どちらも，これまでの回で学んだことがそのままつながります．

限界1：機械学習の予測は「相関」に基づく#

ミニ分類器が学んだのは「『無料』という単語と迷惑メールというラベルが一緒に現れやすい」というパターンでした．カフェの例で学んだのは「時間帯と客数が連動する」というパターンでした．つまり，機械学習が学んでいるのは，第5回の言葉で言えば相関（変数どうしが一緒に動く関係）であって，因果（一方が他方を引き起こす仕組み）ではありません．相関を因果と取り違えてはならないことは，機械学習の定番解説でも明示的に警告されています [Domingos, 2012]．

第5回の結論を思い出してください——予測には相関で足りることがあるが，対策（介入）には因果がいる．傘を持つ人が多い日は渋滞しがちだ，というパターンは，傘が渋滞の原因でなくても渋滞の予測には使えます．しかし「では渋滞を減らすために傘を禁止しよう」は明らかにナンセンスです．機械学習はまさにこの「傘で渋滞を予測する」ことをやっています．だから，機械学習の予測が当たっていても，「予測に使われた要因を操作すれば結果を変えられる」とは限りません．たとえば「参考書の購入額が多い学生ほど成績が良い」と学習したAIがあっても，参考書を買い込むだけで成績が上がるわけではないのです．AIの予測を「原因の発見」と読み替えてはいけない——これが1つめの限界です．

限界2：データの偏りをそのまま学ぶ#

もう1つの限界は，もっと社会的な影響の大きい問題です．機械学習は与えられたデータからパターンを学ぶ——ということは，与えられたデータが偏っていれば，その偏りごと忠実に学ぶということです．

第2回で学んだ「標本の偏り」を思い出してください．偏った標本からどんなに丁寧に計算しても，正しい結論は得られませんでした．機械学習もまったく同じ構図です．しかも機械学習の場合，偏ったデータから学んだ判断が自動化されて大規模に実行されるため，影響が桁違いに大きくなります．

たとえば，過去に特定の属性の人ばかりを採用してきた組織の採用データで「良い応募者」を予測するAIを学習させると，AIは「その属性であること」を良い応募者のパターンとして学び，特定の属性に不利な判断を自動で繰り返すおそれがあります．AI自身に悪意はありません．データに刻まれた過去の偏りを，与えられたとおりに学んだだけです．しかしその結果は，採用・融資・入試といった人生を左右する場面での不公平につながりかねません．

この問題は，「AIの公平性」としていま世界中で議論されており，法や倫理の観点からの検討が欠かせません．次回の第9回「データと法」では，まさにこの「アルゴリズムの公平性・差別」の問題を，個人情報保護や著作権とあわせて扱います．今回学んだ「機械学習はデータの偏りをそのまま学ぶ」という仕組みが，その議論の前提になります．

活用事例：第1回のAIたちの正体——「例と正解から学ぶ」で読み解く#

第1回では，社会におけるAI・データ活用事例として，医療の画像診断支援，交通の需要予測，マーケティングの推薦システムなどを紹介しました．当時は「大量のデータからパターンを学習するらしい」としか言えませんでしたが，今のみなさんは，その仕組みを自分の言葉で説明できるはずです．

事例：あのAIたちは何を「学習」していたのか

画像診断支援（分類）．「医用画像」と「病変あり／なし（医師の診断）」という例と正解のペアを大量に学習し，新しい画像に対して病変の疑いを判定する教師あり学習の分類です．迷惑メールフィルタが件名の単語を手がかりにしたように，画像診断AIは画像の中の模様や形のパターンを手がかりにします．この分野では2017年時点で300を超える研究が報告されるほど活発に研究が進んでいます [Litjens and others, 2017]．

需要予測（回帰）．「過去の日時・曜日・天候・イベントなどの状況」と「そのときの実際の利用者数」のペアを学習し，将来の利用者数という数値を予測する回帰です．カフェの来店客数の例をそのまま大規模にしたものと考えられます．正解ラベルを人がつける必要がなく，過去の実績データがそのまま「正解」になるため，データが自然に貯まり続けるのもこの分野の特徴です．

推薦システム（好みの予測）．第1回で見たとおり，基本のアイデアは「行動が似ている人どうしは，好みも似ているだろう」でした．「ユーザーの行動履歴」から「その人が次にクリック・購入しそうな商品」を予測する，機械学習の一種です [Wang and others, 2021]．「この商品を良いと思うか」の正解は，ユーザー自身のクリックや購入という行動が毎日教えてくれます．

こうして見ると，見た目のまったく違う3つのAIが，どれも「例と正解のペアからパターンを学び，新しい入力に対して予測する」という同じ原理で動いていることが分かります．このような，入力されたデータを分類したり数値を予測したりするタイプのAIを，本講義では識別・予測系AIと呼ぶことにします．迷惑メールフィルタも，スマホの顔認証も，音声認識も，みなこの仲間です．社会で長く活躍してきたAIの大部分は，識別・予測系AIなのです．

注釈

発展：深層学習（ディープラーニング）——画像や音声を扱えるようになった理由

ここまでの例では，「件名の単語」や「時間帯」のような分かりやすい手がかり（判断材料）を使いました．しかし画像や音声が相手だと，「何を手がかりにすべきか」を人間が決めること自体が難しくなります．写真に写っているのがネコだと見分ける手がかりを，ルールとして書き出せないのと同じです．

この壁を破ったのが深層学習（ディープラーニング，deep learning）です．深層学習は，人間の脳の神経回路を大まかにまねた「ニューラルネットワーク」を何層にも深く重ねたモデルで，手がかり（特徴）そのものをデータから自動的に学び取れることが最大の特徴です [LeCun et al., 2015]．2010年代に画像認識や音声認識の性能を飛躍的に向上させ，第1回で見た画像診断支援 [Litjens and others, 2017] や顔認証を実用レベルに押し上げたのは，この技術です．第10回で扱う生成AIも，深層学習の延長線上にあります．

ただし，深層学習も「例と正解のペアから学ぶ」「相関に基づいて予測する」「データの偏りをそのまま学ぶ」という機械学習の基本性質と限界を共有しています．モデルが高度になっても，この章で学んだ見方はそのまま通用します．

まとめ#

今回の内容を振り返りましょう．

  • 機械学習は，人がルールを書く代わりに，データからパターンを学ばせて予測や判別を行う技術です [Jordan and Mitchell, 2015]．ルールを書き出せない仕事・状況が変わり続ける仕事で威力を発揮します．

  • 中心となる学び方は，例と正解のペアから学ぶ教師あり学習です（正解なしでグループを見つける教師なし学習もあります）．タスクは，カテゴリを当てる分類（迷惑メール判定など）と数値を当てる回帰（来店客数の予測など）に大別されます．

  • 「学習」の正体は，ミニ迷惑メール分類器で見たように，データから判断材料を数え上げることでした．学んだ内容はすべてデータ由来であり，データにないことは学べません．

  • 機械学習の目標は，学習データへの当てはまりではなく，新しいデータで通用する汎化です．学習データの偶然のゆらぎまで「暗記」してしまう過学習を見抜くために，学習データとテストデータを分けて評価します [Domingos, 2012]．

  • 精度評価には落とし穴があります．不均衡なデータでは「全部通常」と答えるだけで正解率99%になり得るため，正解率だけでなく見逃しと誤検知の中身を，用途に照らして確認する必要があります．

  • 画像診断支援・需要予測・推薦システムなど，社会で活躍するAIの多くは「例と正解から学ぶ」識別・予測系AIです．その予測は相関に基づくため因果の説明にはならず（第5回），データの偏りをそのまま学ぶため公平性の問題を引き起こし得ます（第2回・第9回）．

機械学習を学んだことで，みなさんは「AIはどう学ぶのか」という問いに，仕組み・評価・限界の3つの面から答えられるようになりました．次回の第9回「データと法」では，データとAIの利活用を支える法制度——個人情報保護法・著作権——と，今回布石を打った「アルゴリズムの公平性」の問題を学びます．そして最終回の第10回「生成AI」では，今回の識別・予測系AI——データから「見分け方・予測の仕方」を学ぶAI——に対して，データから「コンテンツの作り方」を学ぶAI，すなわち生成AIを扱います．今回の内容は，そのままその土台になります．

確認問題#

問1（事例判断型）．ある企業が「不良品を99.2%の正解率で見分けるAI検品システム」を宣伝しています．この工場で作られる製品のうち，不良品は全体の約0.5%だとわかっています．この「正解率99.2%」という数字だけでこのAIを高性能と判断してはいけない理由を説明してください．また，このAIの実力を確かめるには，追加でどんな数字を確認すべきでしょうか．

解答と解説

不良品が全体の0.5%しかない不均衡なデータでは，中身が何もないシステム——すべての製品を「良品」と答えるだけのシステム——でも，正解率は約99.5%になります．つまり正解率99.2%は，「全部良品」と答えるだけのシステムを下回っており，不良品を見つける実力の証拠にはまったくなりません．これが精度評価の落とし穴です．

実力を確かめるには，間違いの中身を分けて確認する必要があります．具体的には，(1) 不良品のうちどれだけ見逃したか（見逃しは市場への不良品流出につながる），(2) 「不良品」と判定したもののうちどれだけが誤検知（実際は良品）だったか，の2つです．さらに，その数字が学習に使っていないデータで測られたものかどうかも確認すべきです．

問2（知識確認型）．次の（ア）〜（エ）のタスクを，分類と回帰に分けてください．

  • （ア）スマホの顔認証で，カメラに映った顔が持ち主本人かどうかを判定する

  • （イ）過去の販売実績から，ある弁当店の明日の来店客数を予測する

  • （ウ）レントゲン画像に病変の疑いがあるかないかを判定する

  • （エ）地図アプリで，現在の道路状況から目的地への所要時間（分）を予測する

解答と解説

  • 分類：（ア）と（ウ）．正解が「本人か別人か」「病変ありかなしか」というカテゴリだからです．

  • 回帰：（イ）と（エ）．正解が「来店客数（人）」「所要時間（分）」という数値だからです．

どちらも「例と正解のペアから学ぶ」教師あり学習である点は共通で，当てたい正解がカテゴリなら分類，数値なら回帰と呼び分けます．

問3（事例判断型）．ある学生チームが，過去の気象データから翌日の売上を予測するモデルを作り，「手持ちのデータ全部を使って学習させたところ，そのデータに対する予測の誤差がほぼゼロになった．誤差ほぼゼロの超高精度モデルが完成した」と喜んでいます．このチームの評価方法の問題点を，この章で学んだ言葉を使って2つ指摘してください．

解答と解説

問題点は次の2つです．

  1. 学習データでの成績で実力を評価していること．手持ちのデータ全部を学習に使ってしまったため，このモデルの実力を測るためのテストデータが残っていません．学習に使ったデータに対する誤差は，モデルの本当の実力（汎化の能力）の証明にはなりません．

  2. 誤差ほぼゼロは，むしろ過学習の疑いが濃いこと．現実の売上データには偶然のゆらぎが必ず含まれるため，誤差がほぼゼロということは，モデルがそのゆらぎ（ノイズ）まで「暗記」してしまっている——過学習している——可能性が高いと考えられます．多項式の次数15の例と同じで，このようなモデルは新しいデータに対してはかえって大きく外すおそれがあります．

正しい手順は，データをあらかじめ学習データとテストデータに分け，学習に使っていないテストデータでの誤差でモデルを評価することです．
