# 講義スライド（Marp）編集方針

本文書は，「データサイエンス・リテラシー」の授業動画用スライドの編集方針を定めるものである．スライドの**見た目の文法**（サイズ・配色・文字数・レイアウトパターン）は [Marp-style-guide.md](Marp-style-guide.md) に全面準拠する（本文書では繰り返さない）．本文書が定めるのは，**講義ノートからスライドをどう作るか**という編集上の方針である．

## 1. 位置づけ

- スライドは**授業動画（30〜45分/回）の収録用教材**である．[curriculum.md](curriculum.md) の教材方針に従い，**講義ノート（Jupyter Book）をベース資料として，その内容を圧縮・ピックアップして作成する**．
- 分担は「スライド＝授業の本流，講義ノート＝詳細と補足の完全版」．スライドに載せなかった詳細（丁寧な説明・確認問題・参考文献）は講義ノートが引き受けるので，**スライドに情報を詰め込まない**（スタイルガイド3節・31節の思想と一致）．
- 教員の口頭説明が主，スライドは補助（スタイルガイド1節）．したがってスライドの本文は「話の要点の提示」であり，読み上げ原稿ではない．

## 2. ファイル構成とビルド

```text
slides/
├── themes/
│   └── lecture.css        # スタイルガイド27節のテーマを実装（全回共通）
├── assets/
│   └── chNN/              # スライド専用画像（PlotlyのPNG書き出し等）
├── ch01-what-is-ds.md     # 1回＝1ファイル．スラッグは講義ノートの章ファイルと一致させる
├── ch02-data-collection.md
├── ...
└── ch10-genai.md
```

- **1回＝1つのMarp Markdownファイル**とし，ファイル名は講義ノートの章ファイル（`chapters/chNN-*.md`）とスラッグを一致させる．
- ビルドは **marp-cli**（`npx @marp-team/marp-cli`．動作確認済み：v4.5.0）を用いる．標準出力は**PDF**（配布・アーカイブ用）とし，収録時のプレビューにはHTMLモードを使ってよい．
- フロントマターはスタイルガイド28節のテンプレート（`marp: true / theme: lecture / size: 4:3 / paginate: false / math: mathjax`）に従う．
- ビルドコマンド（リポジトリルートから）：

  ```bash
  # PDF出力（配布用．_build/ 以下はgitignore済み）
  npx @marp-team/marp-cli --theme-set slides/themes/lecture.css --allow-local-files \
      slides/chNN-*.md -o _build/slides/chNN.pdf

  # PNG書き出し（目視検証用．1スライド1枚のPNGが出る）
  npx @marp-team/marp-cli --theme-set slides/themes/lecture.css --allow-local-files \
      --images png slides/chNN-*.md
  ```

  ローカル画像（figures/のSVG等）を含めるため **`--allow-local-files` が必須**である．また，PNG変換とPDF変換を`&&`で連結して連続実行するとヘッドレスブラウザが競合してハングすることがあるため，**変換コマンドは1つずつ実行**する．
- **執筆上の注意（Markdownの段落分割）**：`.hero` 内などで行を分ける場合は，**行末に半角スペース2つ**を置く方法を使い，**行頭を `<span>` などのHTMLタグで始めない**（行頭のHTMLタグはMarkdownの段落を分割し，行間が開きすぎる）．強調spanは行の途中に置くか，行全体を1行で書く．
- ビルド成果物（PDF）はGitにコミットせず，公開方法（序章の予定表からのリンク）は初回のビルドフロー確立時に決める．

## 3. 講義ノート→スライドの変換規則

### 3.1 構成の対応

講義ノートの節構成（`##`）をスライドの骨格としてそのまま使う（設計方針の「1節≈スライド1ブロック」の回収）．1回分の定型構成：

| 順序 | スライド | 対応する講義ノートの節 |
|---|---|---|
| 1 | 表紙（回番号・タイトル・担当者） | 章タイトル |
| 2 | この回で学ぶこと | 「この回で学ぶこと」（箇条書きをそのまま圧縮） |
| 3〜 | 導入事例 | 「導入：〜」 |
| 中盤 | 本文ブロック（節ごとに数枚〜十数枚） | 本文セクション |
| 終盤 | 活用事例 | 「活用事例：〜」 |
| 終盤 | まとめ・次回予告 | 「まとめ」 |
| 最終 | 講義ノートへの誘導 | —（確認問題・詳しい説明・文献は講義ノートで，の1枚） |

### 3.2 圧縮の原則

- **「教科書を縮小して貼る」の禁止**（スタイルガイド31節）．講義ノートの段落をそのまま貼らず，各スライドの中心メッセージを1つ決めてヒーローメッセージ＋図に変換する．
- **ノートの太字キーワード＝スライドの赤紫強調語**として対応を固定する．ノートで太字定義された用語（curriculum.mdのキーワード）は，スライドでも同じ表記で登場させ，初出スライドで赤紫にする．これにより動画→ノート→小テストで用語が揺れない．
- 講義ノートの**事例・比喩の言い回し**（「黒幕」「名札を裏返す」「味見」「足あと」等）をスライドでもそのまま使う．教材間で語彙を一致させる．
- 文体は**体言止め・短文中心**とし，スタイルガイドの文字数規則（本文60〜100文字，150文字で分割）に従う．句読点を使う場合は「，．」．
- 確認問題・「さらに学ぶために」（参考文献）はスライド化しない．文献への言及が必要な場合は「詳しくは講義ノートへ」で誘導する．
- 数式は講義ノートと同じ範囲（高校数学レベルの最小限．設計方針8節）で使ってよい．見せ方はスタイルガイド18節（単独で大きく・赤い矢印で部分を指す・文章で式全体を説明しない）に従う．

### 3.3 段階説明の使いどころ

スライド複製＋グレーアウトによる段階説明（スタイルガイド15節Pattern D・16節）は，次の箇所で積極的に使う：

- 仕組みの順を追った説明（例：第10回「次の語の予測」ループ，第8回の学習→予測の2段階）
- 対比の提示（例：第7回の適切なグラフ→だますグラフ，まず片方だけ見せる）
- 一覧からの絞り込み（例：だますグラフの手口一覧→1つずつ解説）

## 4. 収録時間の制約と分量・パート分割

### 4.1 収録時間30〜45分は一次制約（最重要）

- **1回分のスライドで収録した動画が30〜45分に収まること**を，枚数より上位の制約とする（curriculum.md「動画の長さ」の遵守）．スライド枚数はこの時間から逆算する従属的な目安である．
- 時間が超過しそうな場合は，話す速度を上げるのではなく**内容をスライドから削って講義ノートに移す**（「詳しくは講義ノートへ」の分担を使う）．講義ノートの内容をすべてスライド化する必要はない．
- **時間見積もりの運用**：
  - 設計時：**1枚あたり平均45秒**で見積もる（40枚≈30分，60枚≈45分．これが枚数目安40〜60枚の根拠）．段階説明の複製スライドは1枚15〜20秒で数える．
  - 各スライドの発表者ノート（6節）の要点量を「45秒で話せる分量」の目安として使う．
  - 検証時：パイロット（第1回）で**通し音読による実測**を行い，1枚あたりの実測平均を算出して以降の回の見積もり係数を更新する．各回の完成時にも要点の音読で概算確認し，45分超過が見込まれる場合は削減してから収録に進む．

### 4.2 パート分割

- 動画を**15分×2〜3パート**に分割する場合に備え，**本文ブロックの境界をパート境界として設計する**（2パート≈30分，3パート≈45分で，パート単位でも時間管理する）．
- パートの先頭には「このパートで扱うこと」を1枚置き，パート末尾には小さな区切り（ここまでのまとめ）を置く．
- 各パートが「導入（つかみ）→本文→小まとめ」で完結するよう，節の配分を調整する．**1パートが15分を大きく超える設計にしない**．

## 5. 図の扱い

1. **講義ノートのSVG図（figures/）は配色無変換でそのまま流用する**（確定方針）．ノートとスライドで同一の図を見せることで学生の認知負荷を最小化する．配色（青・橙）がMarpパレット（濃紺・赤紫）と異なることは許容する．Markdownから相対パス（`../figures/chNN/...svg`）で参照する．
2. **Plotlyグラフは静止画PNGにして掲載する**．書き出したPNGは `slides/assets/chNN/` に置く．インタラクティブな操作（ホバー・ズーム）は，動画内で講義ノートの該当ページを実演して見せる（「手元で動かしたい人は講義ノートへ」の誘導と併用）．
3. **スライド専用に新規作成する図**（スライドでしか使わない模式図・矢印図など）は，スタイルガイド22〜25節（白背景・フラット・限定図形・4色以内）に従う．講義ノートにも役立つ図であれば，スライド専用にせず figures/ の図として作成して両方から使う（[figures.md](figures.md) の手順で作成）．
4. 図の主従：図を説明するスライドでは図を最大化する（スタイルガイド14節）．講義ノートの図が横長でスライド（4:3）に収まりにくい場合は，図の作り直しではなく**トリミングまたは段階提示**（左半分→右半分）で対応する．

## 6. 発表者ノート（収録台本の骨子）

- 各スライドにMarpのコメント記法（`<!-- -->`）で**口頭説明の要点**を書く．収録時の台本骨子であり，話し言葉の完全原稿ではない（要点2〜4行）．
- 発表者ノートには，そのスライドが対応する**講義ノートの節見出し**を1行目に書く（例：`<!-- ノート5節「交絡——隠れた第3の変数」／ポイント：気温が黒幕．売上と事故に因果はない -->`）．収録時に詳細を確認しやすくし，ノート改訂時の追従漏れも防ぐ．

## 7. 品質管理

1. **ビルド検証**：marp-cliでPDFを生成し，エラー・レイアウト崩れがないことを確認する．
2. **目視検証**：`marp --images png` でスライドをPNG書き出しし，画像を目視確認する（図作成と同じ検証ループ）．文字のはみ出し・図の潰れ・強調の過剰を点検する．
3. **スタイルガイド準拠チェック**（各回の完成時）：
   - 1スライド1メッセージになっているか
   - 本文が文字数上限（150文字）を超えるスライドがないか
   - 赤紫の強調が1スライド1〜3箇所に収まっているか
   - レイアウトパターンが5〜6種類に収まっているか
4. **内容の整合チェック**：スライドの用語・数値・事例が講義ノートと一致しているか（キーワードの表記揺れ・数値の食い違いは不可）．

## 8. 作成の進め方

1. **テーマ実装**：`slides/themes/lecture.css` をスタイルガイド27節どおりに実装し，ビルド環境（marp-cli）を確認する．
2. **パイロット（第1回）**：第1回のスライドを1本完成させ，枚数・粒度・図の流用感・発表者ノートの書き方を検証する．あわせて**通し音読で収録時間を実測**し（4.1節），30〜45分に収まることを確認する．このパイロットで本方針の数値目安（枚数・1枚あたり秒数）を必要に応じて改訂する．
3. **展開**：残り9回を展開する．講義ノートと同様，回ごとに並行作成できる．
4. **スライド化との往復**（設計方針9.3節の運用）：スライドに圧縮しにくい箇所（節が長すぎる・要点が抽出できない）が見つかった場合は，講義ノート側の節構成を修正する．
5. **改訂の連動**：講義ノートを改訂したら，発表者ノートの節参照を手がかりに対応スライドを点検する．

## 9. 本方針で定めないこと

- 動画の収録・編集方法（画面構成・録音環境など）は別途定める．
- スライドPDFの配布方法（序章の予定表からのリンク・公開タイミング）は，動画公開ルール（設計方針5.1節）と合わせて運用時に決める．
